# 馬偕通識分享區 v2

馬偕醫學院通識課程的學生修課心得。純靜態網站，放在 GitHub Pages 上。

設計者 **syaouei**｜資料與前身站台 by **Bean1450**
（[舊站](https://haoyu050735.github.io/MMCGeneralCourse/) · [原始碼](https://github.com/haoyu050735/MMCGeneralCourse)）

---

## 本機開發

```bash
node scripts/dev-server.mjs
```

然後開 <http://localhost:8080>。

不要直接雙擊 `index.html`：瀏覽器對 `file://` 的 ES Module 與 `fetch`
都套用 CORS，兩者都會被擋。上線到 GitHub Pages 沒有這個問題。

沒有 `npm install` —— 這個專案沒有任何相依套件。`package.json` 存在的
唯一理由是 `type: module`，讓 Node 能直接 import `js/` 底下的模組。

| 指令 | 用途 |
|---|---|
| `npm run dev` | 本機伺服器 |
| `npm run sync` | 手動跑一次投稿同步 |
| `npm run validate` | 驗證 `data/courses.json` |
| `node scripts/migrate-legacy.mjs` | 一次性：舊站 HTML → courses.json |

## ⚠️ 完全免審核的取捨

**這個站沒有人工審核。** 投稿通過自動品質閘就會直接出現在網站上，
不需要任何人按下任何按鈕。

這是刻意的設計，因為舊站的投稿要維護者手動改 HTML 才會上線，結果就是
投稿長期積著沒人處理。但它有代價，而且代價是真的：

> **惡意內容有可能短暫出現在站上。**
>
> 自動閘只能擋掉「明顯」的濫用 —— 格式錯誤、字數異常、命中封鎖字表、
> 同一分鐘大量提交。它擋不掉寫得像正常心得的不實指控、擋不掉封鎖字表
> 裡沒有的新髒話、也擋不掉針對特定教師的協同抹黑。

真正的補救手段是後台（`#/admin`）：隱藏心得、加入抑制清單、編輯內容。
詳見下面「內容進到站上的兩條路」。

### 為什麼抑制清單是必要的

投稿有兩條路進到畫面上：

1. **烘焙資料** `data/courses.json` —— 每 6 小時由 GitHub Actions 同步
2. **即時 CSV** —— 瀏覽器直接讀 Google 試算表，讓剛投稿的人立刻看到

關鍵在第二條：**CSV 是即時的，所以改 `courses.json` 殺不掉惡意內容。**
下一個訪客的瀏覽器還是會從試算表把它讀回來。

`data/suppressed.json` 是唯一有效的封鎖機制 —— `store.js` 在渲染前把
抑制清單同時套用到兩條路上。後台的「隱藏」動作一定要寫進這個檔案，
只改 `courses.json` 是沒有用的。

## 自動品質閘

規則寫在 [`js/gate.js`](js/gate.js)，**執行期與建置期共用同一份程式碼**。
兩邊各寫一份的話遲早會有一邊漏掉某條規則，而漏掉的那邊會是使用者真正
看到的那一邊。

| 情況 | 處置 |
|---|---|
| 必填缺漏、代碼／學期格式錯誤、領域不存在 | 待審 |
| 評分超出範圍（星級 1–5、甜涼 0–10、成績 0–100） | 待審 |
| 內文少於 10 字或超過 2000 字 | 待審 |
| 命中 [`scripts/blocklist.txt`](scripts/blocklist.txt) | 待審 |
| 同一分鐘內超過 5 筆投稿 | 該分鐘全部待審 |
| 疑似個資（Email／手機／身分證／市話） | **自動遮罩後放行** |
| 與同課程既有心得相似度 > 0.95 | 丟棄（重複送出） |

**預設是「待審」而不是「丟棄」**：擋錯了還救得回來，丟錯了就沒了。
待審項目進 `data/quarantine.json`，後台可以逐筆放行或永久丟棄。

封鎖字表只收**辱罵與人身攻擊**，不收**負面評價**。
「這堂課很爛」「老師很機車」是心得，而且是這個站存在的理由 ——
擋掉它們等於把站變成公關頁。

## ⚠️ 回應試算表是公開唯讀的

純靜態網站沒有後端，只能靠「已發布的試算表 CSV」當免費的唯讀 API。
也就是說 **所有投稿內容任何人都讀得到**。

因此：

- 表單**絕對不可以**開啟「蒐集電子郵件地址」
- 表單裡**不可以**有姓名、學號、班級欄位

加了就會連同心得一起公開在網路上。`sync-submissions.mjs` 偵測到疑似
個資欄位時會在 Actions log 大聲警告，並且不把該欄寫進資料檔 ——
但那時外洩已經發生了。

## 資料

所有內容在 [`data/courses.json`](data/courses.json)，單一真實來源。

- `data/suppressed.json` —— 永不顯示的心得 id
- `data/quarantine.json` —— 被閘門擋下、待後台處理
- `data/teacher-pinyin.json` —— 教師姓名 → 課程 id 用的拼音
- `migration-report.md` —— 舊站遷移的逐筆報告

遷移自舊站的 258 則心得一則都沒有丟。舊資料大量缺項（甜度／涼度只有
41% 有值），**缺項一律是 `null`，不補值、不用平均數填空、不用 0 代表
沒有資料**。統計只計入非 null 的值並永遠標示樣本數。

教師拼音刻意用人工維護的對照表而不是 pinyin 套件：課程 id 會進網址，
套件版本變動造成的 id 漂移等於所有分享出去的連結一次全壞。
